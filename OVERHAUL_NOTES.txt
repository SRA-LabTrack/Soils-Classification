SOILS v1.10.27 OVERHAUL

SOILS v1.10.27 REQUEST DELIVERY HOTFIX

- Farmer placement submission no longer waits for Support Chat to succeed. The spatial_requests row is saved first and is authoritative.
- Admin Support Inbox reads pending spatial_requests directly, so a request remains clickable even if support_messages is missing, partially migrated, or temporarily slow.
- Support request notifications use a short best-effort timeout and legacy support_messages schemas fall back without request-link columns.
- Farmer request retries are idempotent through a stable client_request_id, preventing duplicate approvals after a timeout/retry.
- Farmer request API/Appwrite calls now have explicit timeouts instead of leaving the modal stuck on Saving forever.
- Admin Realtime listens to both support_messages and spatial_requests independently.
- Farmer request modal now says FARMER REQUEST instead of ADMIN CONTROL.

SOILS v1.10.27 FARMER REQUEST WORKFLOW

- Farmer can request Sensor, Soil Plot, or Drone Mapping placements from the farm map.
- Requests accept plotted map points or GPS coordinates and must stay inside the approved Farm Boundary.
- Pending requests are separate from published spatial records and do not affect Statistics.
- Every request creates a clickable Admin Support Inbox message.
- Admin can open the request from any section, fly to its exact point/polygon, and Approve or Reject.
- Approval publishes the requested spatial record; rejection leaves published map data untouched.
- Farmer receives submission and decision messages through Support Chat.
- Run npm.cmd run setup:appwrite once after upgrading to create spatial_requests and support request-link columns.
